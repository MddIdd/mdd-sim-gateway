# Asterisk modules this gateway ships. Everything else built by the reference build is
# deleted from /usr/lib/asterisk/modules in the build stage, BEFORE runtime-packages.txt is
# derived (engine/Dockerfile) — that is the whole point: the closure is computed by running
# ldd over modules/*.so, so a module that is never loaded still drags its whole library
# closure into the runtime image. libicu (37 MB) rode in on res_calendar_icalendar,
# lpcnetfreedv (15 MB) on codec_codec2, perl-libs + net-snmp (17 MB) on res_snmp — none of
# which this product can even load, because modules.conf.j2 already noloads them.
#
# Why a keep-list of built modules rather than menuselect --disable:
#   - The compile stays byte-identical to the sysmocom reference build. We only choose what
#     to ship, so any bug report is reproduced by simply not deleting.
#   - Deleting in its own layer after `make install` leaves the expensive compile layer
#     cached; only the closure derivation and the strip/staging layer below it rebuild.
#   - menuselect's dependency tree is implicit and transitive, and it changes across Asterisk
#     versions. A list of filenames fails loudly and locally instead.
#
# modules.conf.j2 keeps its noload list unchanged, as defence in depth. noloading a module
# whose file is absent is silent — verified, no extra startup warnings.
#
# CONTRACT: every name below must exist after `make install` or the build fails. Removing a
# name is cheap; adding one back is a one-line change. When in doubt, keep it — a missing
# codec/format/res_pjsip_* module usually shows up as a silent call, not as an error.
#
# Verified: with exactly this list, Asterisk loads all 126 modules with zero load failures
# and the same three startup warnings as the untrimmed image.
